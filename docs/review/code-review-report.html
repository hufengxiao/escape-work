引擎层审查发现

2×P0 6×P1 7×P2
P0 引擎层直接依赖 UI 层，硬性分层违规 gameEngine.js:13
问题gameEngine.js 顶部 import { toast } from '../ui/toast.js'，并在 travelToNode / executeAction / resolveEncounterChoice 中直接调用 toast.show() 达 4 处。引擎层被 DOM 污染，无法在纯 Node 环境运行，也无法做引擎单测。已核验：这是唯一一处 engine → ui 的 import。
对照main.js 已证明正确分层方向——UI 持有 engine 引用（UIRenderer(gameState, gameEngine)），引擎只应发事件。
修复：删除 import toast，改为 this.state.emit('ui:toast', { msg, type, duration })，由 UI 层订阅。改动约 5 处调用点。
P0 存档字段类型污染：hardcoreWins 可能是对象而非数字 gameState.js:208 / :221
问题loadPersistentData 的两条分支默认值类型不一致：:208 兜底为 {} 空对象，:221 兜底为 0 数字。而 gameEngine.js:402 对它做 (hardcoreWins || 0) + 1 累加——若加载出的是 {}（空对象为真值，|| 0 不生效），结果是字符串 "[object Object]1" 或 NaN，被永久写回存档且无法自愈。
影响硬核模式胜场统计永久损坏，连带 renderer.js:2489 的生涯战绩展示。
修复：统一为数字类型，加载时对每个数值字段做 Number(x) || 0 归一化；:208 改为 0。
P1 triggerEnding 缺少幂等短路，战绩/经验可重复累加 gameEngine.js:390
问题函数入口没有 if (this.state.currentEnding) return;。遭遇选项触发结局后，checkVitalConditions()（:385）可能因体力 ≤0 再次调用它，导致 victories / gamesPlayed / slackerExp 重复 +1。已核验源码确认无该守卫。
修复：函数首行加 if (this.state.currentEnding) return;
P1 遭遇事件状态写在全局常量对象上，跨局污染 gameEngine.js:330 / :467
问题RANDOM_ENCOUNTERS 是模块级数组，代码直接执行 selected.hasOccurred = true 修改全局对象，靠 restart 手动遍历重置。任何漏调 restart 的开局路径都会让标记残留，导致后续若干局都遇不到随机事件。状态藏在 data 模块里，破坏单一数据源。
修复：把 hasOccurred 移入 state.encounterHistory，由 reset() 统一初始化。
P1 反向老板模式时间推进整除截断，18:05 永远到不了 reverseBossEngine.js:86
问题this.currentMinute += Math.floor(20 / this.maxTurns)，当 maxTurns=8 时 floor(2.5)=2，8 回合只推进 16 分钟到 18:01，与设计的「17:45 → 18:05」不符，UI 展示时间与设计意图不一致。
修复：改用累计分钟数 addMinutes(totalMinutes / maxTurns)，避免整除丢失精度。
P1 定身技能在同一回合被立即清除，实际不生效 reverseBossEngine.js:252 / :291
问题useSkillDeadlyAt / useSkillEmergencyMeeting 设置 isEmployeesStunned=true 后调用 stepTurn(false)，而 :291 无条件将 isEmployeesStunned 置回 false。宣称「定身 1 回合」的技能实际上对员工移动毫无作用。
修复：用独立的 stunTurns 计数器跨 stepTurn 递减，而非同回合清零。
P1 巡逻威胁标记用裸 Math.random，破坏种子可复现性 patrolManager.js:111
问题node.hasBossThreat = Math.random() < 0.5。该函数被 stepPatrol 和 triggerDecoy 多处调用，同回合内每次调用结果都不同，UI 上会出现威胁标记闪烁；同时与项目宣称的「受控 PRNG / 每日种子复现」设计目标直接冲突。
修复：改用 PRNG(state.dailySeed) 派生，或基于 node.index 的确定性哈希。
P1 加班事件时间筛选条件恒真，随机事件与小时无关 overtimeEngine.js:163
问题条件 currentHour >= ev.minHour || (currentHour <= 6 && ev.minHour <= 6) 中，白天时第一子句恒真，凌晨时第二子句几乎对所有 minHour<=6 的事件成立。筛选形同虚设，事件会出现在不匹配的时段。
修复：明确定义时间窗区间 [minHour, maxHour] 并校验落入区间。
P2 关键可维护性问题（7 项）
清单 ① mapManager.findNode 为 O(n) 线性扫描且被双层循环反复调用（mapManager.js:134）→ 建 id→node Map 缓存；
② gameState.emit 内部已调 notify()，调用方随后又手动 notify()，一次移动触发 2 次全量渲染；addLog 亦如此（gameState.js:285）→ 引入渲染节流；
③ depth↔zone 映射口径不统一，zone=4 在两处规则不一致，可能导致反复判定 out-of-sync（gameEngine.js:150 vs :136）→ 统一映射表；
④ v1/v2 双份存档加载逻辑重复维护，且同时写两个 key 易漂移（gameState.js:196-246）；
⑤ craftManager.craft 未检查 addItem 返回值，原料已扣、产物可能未加，玩家净损失道具且无提示（craftManager.js:62）；
⑥ 加班/反向老板引擎全程裸 Math.random，未接 PRNG，与主游戏确定性设计割裂；
⑦ applyPerks 用 Math.random 选道具，每日种子模式下同一天开局道具会变（gameState.js:168）。

P0 结局 ending_normal_escape 被引用但从未定义 events.js:550 → endings.js（缺失）
问题events.js:550 在小游戏 QTE 判定的 LATE 分支调用 window.__GAME__.engine.triggerEnding('ending_normal_escape')。
核验已在 endings.js 中逐一比对全部 30 个结局定义——不存在 ending_normal_escape，也无拼写相近项。引擎虽在 triggerEnding 里有 ENDING_CAUGHT_MEETING 兜底，不会抛异常，但玩家在 QTE 失误路径会看到预期之外的结局文案，叙事闭环断裂。

P1 recipes 引用 8 个不存在的成就 ID recipes.js 多处 → achievements.js（缺失）
问题recipes.js 的 unlockAchievement 引用了 achievements.js 中从未定义的成就：ach_craft_master、ach_craft_decoy、ach_craft_bomb、ach_craft_delivery、ach_craft_aura、ach_craft_shield、ach_craft_smoke、ach_craft_p0。

修复：在 achievements.js 补齐这 8 个成就，或统一改为已有的计数式条件（如 ach_alchemy_master）。
P1 成就条件用了错误字段名 r.favor，「全司人脉王」永远无法解锁 achievements.js:151
问题ach_social_butterfly 的条件是 Object.values(state.npcRelations).filter((r) => r.favor >= 80)，但真实字段名是 favorability（npcManager.js:44 初始化、:82 累加确认）。r.favor 恒为 undefined，比较恒为 false。
旁证同一文件 :200 的 ach_intern_mentor 用的却是正确的 r.favorability——同一文件内字段名前后不一致，确认为笔误而非设计。

P1 黑话加成角色 ID 拼写错误，产品经理加成永不生效 buzzwords.js:66

P1 去重 flag 只读不写，电梯老板遭遇防重逻辑形同虚设 events.js:403
问题if (rand < 0.45 && !state.flags.hasEncounteredBossInElevator) 读取该 flag 做去重。

P0 部署 workflow 缺少 permissions 最小化声明 deploy-cloudflare.yml:14-16
问题未声明 permissions，GITHUB_TOKEN 默认获得偏宽松的写权限，而 workflow 同时又使用了可写 secret，违背最小权限原则。
修复：job 顶层加 permissions: { contents: read, deployments: write }；secret 仅在 deploy step 内以 ${{ secrets.* }} 注入，不要放在 job 级 env。
P0 main 分支 secret 缺失时静默跳过部署，无人察觉 deploy-cloudflare.yml:41
问题deploy 条件依赖 env.CLOUDFLARE_* != ''。若 secret 缺失或轮换后忘记配置，workflow 会静默跳过部署并报绿，main 分支可能长期不发布却没有任何告警。
修复：main push 事件下若 secret 缺失应显式 exit 1 失败，让 CI 红灯可见。
P1 sprint5/6 大量测试退化为「读取源码字符串」的伪测试 sprint5.test.js:140-337 · sprint6.test.js:280-292
核心手法 const rendererCode = fs.readFileSync('../src/ui/renderer.js', 'utf-8')，随后断言 rendererCode.includes('id="nav-tab-escape"')、 cssCode.includes('grid-template-columns: repeat(2, 1fr)') 等。已核验源码确认此为真实情况。
为何无效这类断言只验证「源码文件里存在某段文本」，完全不验证运行时行为。把 CSS 规则删掉但保留注释字符串，测试照样通过；反之改名重构会产生大量误报。sprint5 约 12/14 个用例属此风格（T5.1、T5.4–T5.14），实际有效断言不足 20%。
修复：改用 jsdom / Playwright 做真实 DOM 断言，或用 CSS 解析器校验规则是否存在。
P1 UI 层零行为测试，仅验证「能否 new 出来」 sprint5.test.js:46-63
问题断言仅为 typeof ReverseBossView === 'function' 与 bossView.engine instanceof ReverseBossEngine——即只验证 import 成功、类可实例化，不验证任何渲染输出。2573 行的 renderer.js 完全无运行时测试，这也是前述 XSS 与全量渲染问题能长期潜伏的原因。
修复：引入 @vitest/browser 或 jsdom，断言 render() 后的 DOM 结构与文本转义行为。
P1 存档读档 round-trip 从未被验证 sprint4.test.js:137-190
问题现有测试只覆盖 V1→V2 迁移。而 gameState.js:226 savePersistentData() 写入后经 loadPersistentData() 读回的往返一致性从未验证——这正是引擎层 P0 中 hardcoreWins 类型污染能漏网的原因。
修复：新增 save → new GameState → 逐字段断言完全一致 的 round-trip 测试，覆盖所有历史字段。
P1 主包 330 KB，changelog / guide 全量打进首屏 vite.config.js:9-13
实测构建产物：主 JS 330.8 KB（gzip 111 KB）、CSS 99.0 KB、miniGames 分包 39.1 KB。配置中无 manualChunks，且 renderer.js:14-15 静态 import 了 changelog/guide 两个低频弹窗数据。

P2 工程配置缺失项（4 项）
清单 ① vite.config.js 过简：无 minify 显式配置、无 sourcemap（线上排障困难）、无 chunkSizeWarningLimit、无 build.target。已有 base: './'（这点对 Cloudflare Pages 是正确的）；
② package.json 缺工程字段：无 lint/format/typecheck 脚本，无 engines（CI 用 Node 22 但本地无约束），无 repository；无 ESLint / Prettier 依赖与配置；
③ index.html 缺 PWA/SEO meta：无 apple-touch-icon、无 og:image、无 twitter:card、无 canonical；manifest 的图标仅一个 SVG 且声明 192×192 与 512×512 双尺寸（不规范，iOS 不支持 SVG touch-icon）；
④ public/_headers 缺 CSP：已有 X-Frame-Options / X-Content-Type-Options / Referrer-Policy，但没有 Content-Security-Policy——而这恰好是缓解前述 XSS 风险的纵深防御手段。
修复建议：加 Content-Security-Policy: default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'；补 engines: {"node": ">=20"} 与 lint 脚本；增补 PNG 图标与 og:image。
P2 构建警告：同一模块静态 + 动态混合导入，代码分割失效
问题vite build 输出警告：npcManager.js is dynamically imported by events.js but also statically imported。这会导致该模块无法被拆进独立 chunk，代码分割实际失效。
修复：统一为一处静态 import，消除混合导入。
